The Problem & Vision

The Problem

While GPS revolutionized outdoor navigation, satellite signals attenuate heavily inside multi-story concrete buildings. Navigating complex indoor spaces—such as academic blocks, hospitals, transit hubs, and large commercial complexes—remains disorienting. Furthermore, traditional indoor positioning systems rely on dense Wi-Fi access point fingerprinting or external BLE beacons that require costly installation and fail during power outages or emergency evacuations.

Intended Users

Visitors, students, hospital patients, wheelchair users requiring accessible elevator-only routing, and emergency evacuees who need reliable, offline-first indoor navigation that works immediately on standard Android smartphones without external hardware infrastructure.

Reason for Selection

We selected this problem because building an offline-first indoor positioning engine from first principles combines real-time IMU signal processing, 400-particle Monte Carlo probabilistic state estimation, and 3D multi-floor graph routing into a practical, high-impact system.

Our Solution & User Journey

Proposed Solution: IndoorPulse

IndoorPulse is an offline-first Indoor Positioning System (IPS) built natively in Kotlin and Jetpack Compose, paired with a self-hosted AWS EC2 + Backblaze B2 Web Map Console. The core engine operates with zero external beacon dependencies—using hardware IMU sensors (Linear Accelerometer + Rotation Vector), a 400-particle Monte Carlo localization filter constrained by topological corridor geometry, and a 3D Euclidean A* multi-floor router.

The Main User Journey

  • 1. Outdoor-to-Indoor Geofence Handshake: The Outdoor Dashboard monitors live GPS proximity against mapped building geofences (`centerLat`, `centerLng`, `geofenceRadius`) and automatically prompts indoor handoff upon arrival (with manual indoor/outdoor override support).
  • 2. Surveyor Mode & Portable JSON Packaging: An administrator maps the building by placing typed topological nodes (`Building Entry`, `Waypoint`, `Stairs`, `Elevator`, `Washroom`, `Room Door`) and connecting corridors or cross-floor `vertical_portal` edges with full undo/redo history and dynamic touch-snapping, then exports a versioned `.json` map package.
  • 3. Multi-Floor 3D A*, Accessible Mode & Emergency SOS Routing: A user selects any destination across floors, toggles ♿ Accessible Mode to strictly bypass stairs in favor of elevators, or taps the 1-click SOS Nearest Exit button.
  • 4. Live IMU Navigation & Portal Transit State UX: As the user walks, the Dual-Threshold Schmitt Trigger and 400-particle filter advance the gyro-locked navigation chevron along corridors. Entering a stairwell or elevator proximity radius automatically triggers the modal Transit State overlay, pausing PDR step integration during vertical floor transitions.

Live Demonstration Plan

Scenario: End-to-end multi-floor building survey, JSON map export, browser-based 3D A* & Accessible Elevator verification, and live Android PDR navigation.

  • Step 1 (Surveyor & Persistence): Open IndoorPulse on Android, inspect the multi-floor building topology stored in Room SQLite, and export the versioned `.json` map package with UUID translation.
  • Step 2 (Cross-Floor 3D A*, Accessible Mode & SOS): Select an upper-floor room target, toggle ♿ Accessible Mode to observe dynamic rerouting from Stairs to Elevators, or trigger Emergency SOS.
  • Step 3 (Live IMU Walk & Schmitt Trigger): Walk physically with the smartphone—observe the Schmitt Trigger state machine reject hand-shake jitter while the 400-particle filter and gyro-locked chevron track movement and pause automatically inside the vertical portal Transit State.
  • Step 4 (Web Map Console Parity): Load the exported `.json` map into the Web Map Console above (or pull it from Backblaze B2) to inspect 3D-offset floor blueprints and simulate the identical routes in the browser.

System Integration & Architecture

On-Device Algorithmic Stack (Android Kotlin)

  • IMU Sensor Fusion (`KinematicPDR.kt`): Polls `TYPE_LINEAR_ACCELERATION` and `TYPE_ROTATION_VECTOR` via a Dual-Threshold Schmitt Trigger state machine and Fused Biomechanical stride model, eliminating stationary desk drift.
  • 400-Particle Monte Carlo Filter (`ParticleFilter.kt`): Probabilistic localization engine translating World Space headings into Map Space coordinates with corridor edge clamping and resampling.
  • 3D Euclidean A* Router & Accessible Filter: Replaces flat Dijkstra with multi-floor 3D A* heuristics (`dx, dy, dz`), wheelchair-accessible elevator filtering, strict Emergency SOS exit targeting, and proximity-based portal PDR pausing.

UI Layer, JSON Engine & 3-Tier Cloud Stack

  • Jetpack Compose UI (`MapCanvas.kt`, `MainScreen.kt`): Interactive multi-floor blueprint canvas with zoom-clamping, snapping hit-detection, responsive Building Manager dialogs, and outdoor geofence dashboard animations.
  • Room SQLite & JSON Map Engine: Relational `BuildingEntity`, `NodeEntity`, and `EdgeEntity` schemas paired with a custom JSON export/import engine supporting automatic UUID remapping upon import.
  • Self-Managed Cloud Deployment (No PaaS): Static Web Map Console on GitHub Pages communicating with a self-configured AWS EC2 Flask API (`indoorpulse.duckdns.org`) and Backblaze B2 S3-compatible object storage.

Project Status & Architectural Roadmap

Phase 1 Complete (Deployed Core System)

  • Zero-Infrastructure IMU PDR + 400-Particle Filter: Full step detection, biomechanical stride model, corridor topology clamping, and World-to-Map chirality translation.
  • Multi-Floor 3D A*, Accessible Elevator Routing & SOS: Cross-floor pathfinding across `Stairs` and `Elevator` portals, wheelchair-accessible stair-bypass mode, proximity Transit State modal overlay, and 1-tap SOS routing to true building exits.
  • Surveyor Mode & Portable JSON Engine: Multi-floor node/edge placement (`Entry`, `Waypoint`, `Stairs`, `Elevator`, `Washroom`, `Room Door`), undo/redo stack, dynamic touch snapping, and versioned `.json` export/import with UUID translation.
  • Web Map Console & AWS EC2 / Backblaze B2 Gateway: Browser-based 3D A* blueprint simulator and password-protected cloud artifact/map storage.

Phase 2 Planned Extensions (Modular Sensor Clamping)

  • ARCore Visual-Inertial Odometry (VIO) Optical Clamping: Designed as an on-demand optical heading calibration hook for wide, featureless atriums without continuous camera battery drain.
  • Opportunistic Wi-Fi / BLE RSSI Drift Anchors: Modular observation-update hooks in the Particle Filter to passively clamp cumulative IMU drift in buildings where RF beacons already exist.
  • Barometric Auto-Floor Confirmation: Fusing smartphone pressure sensor deltas (`TYPE_PRESSURE`) to auto-confirm stairwell/elevator floor arrival without manual confirmation.
